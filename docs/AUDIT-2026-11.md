## 1. Shrnutí

Zadání předpokládalo „čisté HTTP na 0.0.0.0, `SESSION_COOKIE_SECURE=false`“. To už neplatí: poslední velký commit
(public-internet hardening) přidal loopback bind, TLS vzor pro Apache, bezpečnostní hlavičky, rate limity i systemd sandbox
(oddíl 3). Transportní vrstva je tedy rozumně pokrytá. **Hlavní rizika leží jinde – na hranicích důvěry uvnitř aplikace:**
mezi běžným uživatelem, spouštěnými MCP servery, úložištěm tajemství a admin rovinou.

Nejdůležitější nálezy (podrobně v oddíle 5):

1. **A-01 (Critical, jen při `DEMO_MODE=true`)** – ochrana demo režimu se na REST API neuplatňuje; demo admin může zaregistrovat server s libovolným příkazem.
2. **A-02 (High)** – běžný uživatel může do spouštěného MCP procesu vnést libovolné *názvy* proměnných prostředí (`NODE_OPTIONS`, `LD_PRELOAD`, `PYTHONPATH`, `PATH`, …).
3. **A-03 (High)** – zakázaný uživatel zachová přístup přes dříve vydaný proxy token; token nemá default expiraci ani individuální revokaci.
4. **A-04 (High, architektura)** – spouštěné MCP servery běží se stejným uid jako aplikace; jeden kompromitovaný server = kompromitace všech tajemství vč. master hesla Vaultwardenu.
5. **A-05 (High, podmíněně)** – odkaz pro reset hesla se skládá z hlavičky `Host` (ignoruje `PUBLIC_BASE_URL`); token navíc obsahuje hash hesla.
6. **A-06 (High pro internet)** – výchozí „allow-all“ ACL + automatické zakládání účtů pro kohokoli z AD.
7. **A-07 / A-08 (High)** – OAuth: anonymní DCR a souhlas bez zobrazení `redirect_uri`; relay předává `Authorization` klienta třetím backendům.
8. **A-09 (High)** – uživatel může přepsat *neutajovanou* proměnnou s URL (např. adresu služby) a MCP server pak pošle sdílený admin token na adresu, kterou zvolil uživatel (PoC 13, doplněno při závěrečné kontrole).

Co jsem **nepotvrdil** (pozitivní zjištění): žádný XSS/SSTI ve šablonách, žádný SQL injection, LDAP injection je ošetřen,
v UI ani API neexistuje pole, kam by běžný uživatel zadal URL, kterou mcprack sám volá (klasické SSRF z uživatelského vstupu tedy chybí; nepřímá varianta přes env proměnné je ale A-09),
session cookie má správné příznaky.

Počty: 1 Critical (podmíněný), 8 High (+1 mimo repozitář), 16 Medium (+1 mimo repozitář, +1 neověřený), 5 Low, 1 Info.

## 4. Mapa architektury

### 4.1 Vstupní body

| Skupina | Trasy | Autentizace |
|---|---|---|
| Veřejné | `/login`, `/forgot-password`, `/reset-password/<token>`, `/set-locale/<l>`, `/health`, `/favicon.ico`, `/static/*`, `/api/v1/openapi.json` | žádná (login/reset s rate limitem) |
| Monitoring | `/health/servers` | `Authorization: Bearer MONITORING_TOKEN` (`hmac.compare_digest`), jinak 404 |
| MCP relay | `/proxy/mcp/<token>/<id>` (podepsaný token v cestě); `/proxy/mcp/<id>` jen při `OAUTH_ENABLED` | token `{u,s}` bez expirace; Bearer (OAuth/ApiToken `proxy:access`) |
| OAuth AS (volitelný) | `/.well-known/oauth-*`, `/oauth/register|token|revoke` (anonymní), `/oauth/authorize` (login) | DCR bez autentizace |
| Uživatel | `/`, `/selection`, `/override/<id>`, `/download|view/<client>`, `/icon/server/<id>`, `/account/password`, `/logout` | session cookie |
| Admin | `/admin/*`: servery (CRUD, test, capabilities, autodetect), instalace pip/npm/docker, Vaultwarden/OTel/OAuth wizardy, proxy instance, uživatelé, šablony, audit log | session + `is_admin` |
| REST API | `/api/v1/*` (me, tokens, servers, selections, overrides, config, admin/*) | session cookie **nebo** ApiToken (scopes) |
| CLI | `mcprack user|server|template|secret …`, `flask create-admin`, `audit-archive`, `mcprack-init-config`, `mcprack-mcp-probe` | lokální (root / skupina `mcprack`) |
| Klienti (jiný repozitář) | `mcprack-sync-claude|cursor|vscode` → `GET /api/v1/me/config/<client>` | ApiToken |

### 4.2 Model oprávnění
`User(is_admin, is_active, auth_type local|ldap)` → `UserServerPermission` (ACL; bez řádků = „allow all enabled“, pokud `STRICT_SERVER_PERMISSIONS=false`) →
`UserServerSelection` (co se generuje/relayuje) → `UserServerOverride` (vlastní hodnoty, jen při `allow_user_override`). ApiToken: scopes `profile:read … admin:write`, NULL/`*` = vše.
OAuth token: scope `mcp` pro všechny vybrané servery uživatele (bez per-server omezení). Proxy path token: `{u: user_id, s: server_id}` podepsaný `SECRET_KEY`.

### 4.3 Tok tajemství
Vaultwarden (`bw` CLI, `unlock`→`--session`→`lock`, serializováno flockem v `.bw`) **nebo** lokální Fernet (klíč odvozen z `SECRET_KEY`) →
`secret_store.resolve_server_env` → šifrovaná cache (`.bw/.mcprack-env-cache.json`, TTL 60 s) → `user_proxy._desired_config` → **JSON na disku** `/var/lib/mcprack/user-proxies/u<U>-s<S>.json`
→ `fastmcp run <json>` → stdio dítě (env), nebo hlavička `auth_header_name` při relay na síťový backend.
Klientské konfigurace tajemství **neobsahují** (jen relay URL s path tokenem) – to je správně.

### 4.4 Spouštění procesů a síťová volání
- `fastmcp run <cfg>.json --transport http --host 127.0.0.1 --port <35000+…>` (`user_proxy.py:497-535`), `start_new_session=True`, bez autentizace na loopbacku.
- `bash -c` s `pip`/`npm`/`docker pull` (`installer.py:114-143`), `bw` CLI, `dpkg-query` (ikony, `version.py`), `docker image inspect`.
- Odchozí: relay na `server.url` (`http.client`, bez následování redirectů), LDAP (ldap3), SMTP, OTLP, `bw` → Vaultwarden, health sondy.

### 4.5 Diagnostika dnes
Seznam serverů (`check_stdio_command`, `check_http_reachable` 1,5 s), tlačítko „Test“ (2 s start procesu), „Capabilities“ (`initialize`+`tools/list`+`resources/list`),
handshake při spawnu (`probe_tools`, 15 s), re-probe každých 30 s (jen `initialize`), `/health/servers` pro Zabbix, CLI `server test|probe`. Podrobně v oddíle 7.

## 5. Prokázané nálezy (P / K)

### 5.1 Critical / High

#### A-01 · Critical (jen při `DEMO_MODE=true`) · P · pracnost S
- **Místo:** `api.py:502-614` (create/update/delete serveru); guard `_demo_mode_blocked()` (`admin.py:52`) volaný jen v HTML trasách `admin.py:213,267,576,629,802,844,886,984`; předvyplnění přihlášení `auth.py:207-210`, `config.py:125-126`.
- **Riziko:** Demo režim má zabránit registraci/úpravě serverů, protože `command` se spouští bez sandboxu. API ten zámek nemá (PoC 12: HTML formulář → 302 a server nevznikl; `POST /api/v1/admin/servers` s `command=/bin/true` → **201**). Mimo API se guard netýká ani `server_test_stdio` (`admin.py:653`) a `server_capabilities` (`admin.py:679`), které spouštějí registrované příkazy.
- **Scénář dopadu:** Na veřejné demo instanci se kdokoli přihlásí předvyplněným účtem (`demo/demo`; podle komentáře v `config.py:113-118` jde o admin účet), přes REST API zaregistruje server s libovolným příkazem, vybere ho a zavolá proxy URL. Kód poběží jako uživatel `mcprack` a přečte `/etc/mcprack/env`. Bez `DEMO_MODE` nález nemá dopad.
- **Oprava:** guard přesunout do `before_request` admin blueprintu a `api_admin_required` (mutace serverů, instalace, test, capabilities, import env); doplnit test, který projde *všechny* mutující admin trasy v demo režimu.

#### A-02 · High (Critical, pokud katalog obsahuje servery spouštěné přes node/npx/uvx) · P (chybí validace) / S (exploit) · pracnost S–M
- **Místo:** `catalog.py:681-724` (`parse_user_override_form`), `api.py:314-337` (`_override_put_payload`), `secret_store.py:187-237` (merge), `user_proxy.py:306-316` (`_desired_config`), `user_proxy.py:497-533` (spawn).
- **Riziko:** Názvy klíčů přepisu se nevalidují. PoC 6: běžný uživatel `PUT /api/v1/me/overrides/<id>` s `{"env": {"NODE_OPTIONS": …, "LD_PRELOAD": …, "PYTHONPATH": …}}` → **200**, klíče skončí v `env` předaném spouštěnému procesu. (Použil jsem neškodné hodnoty; exploit jsem nepsal ani netestoval.) Procesově významné proměnné (`NODE_OPTIONS`, `LD_*`, `PYTHON*`, `PATH`, `NPM_CONFIG_*`/`npm_config_*`, `UV_*`, `PIP_*`, `BASH_ENV`, `HOME`, …) mění, *jaký kód* se spustí nebo odkud se stáhne.
- **Scénář dopadu:** Kdokoli s účtem (u zapnutého LDAP *libovolný AD účet*, viz A-06) vybere server a v „vlastních hodnotách“ nastaví proměnnou, kterou runtime interpretuje jako načtení kódu. Při příštím startu procesu běží cizí kód jako `mcprack` – tedy cesta od běžného uživatele k úplné kompromitaci (A-04). Realizovatelnost závisí na konkrétním serveru (S-01).
- **Související:** A-09 (přepis URL klíče posílá sdílený token na cíl uživatele) vzniká ze stejného místa a allowlist z A-02 ho sám nevyřeší.
- **Oprava:** (1) regex názvu `^[A-Za-z_][A-Za-z0-9_]{0,63}$`; (2) *allowlist* – uživatel smí přepsat jen klíče deklarované adminem/manifestem (`env_var_names`, `env_config`, `required_env_keys`, detekované), volný vstup jen s explicitním příznakem na serveru; (3) *denylist* rodin procesových proměnných jako druhá vrstva; (4) stejná pravidla pro admin formulář, API i CLI (`split_override_values` je společné místo).

#### A-03 · High · P · pracnost M
- **Místo:** `catalog.py:467-477` (token → `db.get_or_404(User, …)` bez kontroly `is_active`), `catalog.py:58-81`, `config.py:180-181` (`PROXY_TOKEN_MAX_AGE=None`).
- **Riziko:** PoC 3: u zakázaného účtu vrací proxy token **502** (autentizace prošla, relay se pokusil o spojení) místo 403. Ten samý účet se na `/login` přihlásit nemůže a živá session se po zakázání odhlásí (PoC 11) – zbyl jen tento kanál. Token nemá default expiraci a nelze ho zneplatnit jednotlivě; jediná revokace je rotace `SECRET_KEY`, která zároveň zničí lokálně šifrovaná tajemství (B-16). Procesy zakázaného/smazaného uživatele běží, dokud je nesklidí idle reaper, který se spouští jen při příchozím requestu (B-12).
- **Scénář dopadu:** Zaměstnanec odejde, správce mu zruší účet v UI, ale jeho Claude/Copilot dál volá nástroje (Zabbix, Mastodon, …) s jeho Vaultwarden credentials, dokud někdo nerotuje `SECRET_KEY`.
- **Oprava:** kontrola `is_active` v obou proxy trasách; `token_version` (Alembic, vratná) uložená v tokenu a ověřovaná; default `PROXY_TOKEN_MAX_AGE` (např. 90 dní) s dokumentovanou migrací; `stop_user_server_proxy` při disable/delete uživatele; audit události.

#### A-04 · High (architektura; autor ji zná – komentář v `debian/mcprack.service`) · K · pracnost S (scrub env) / L (izolace)
- **Místo:** `user_proxy.py:506` (`os.environ.copy()`), `:73-74` (předvídatelné porty), `:501-503` (tajemství v JSON); `debian/postinst:147-148` (`/etc/mcprack/env` `0640 root:mcprack`); jednotka (`User=mcprack` pro vše).
- **Riziko:** Spouštěné stdio servery sdílejí uid/gid i cgroup s aplikací. Proto mohou číst `/etc/mcprack/env` (`SECRET_KEY`, `BW_PASSWORD` = **master heslo celého Vaultwardenu**, `BW_CLIENTSECRET`, `LDAP_BIND_PASSWORD`), `/proc/<pid>/environ` gunicornu i `fastmcp` (zdědí celé env), SQLite DB, `.bw/` a `user-proxies/*.json` s tajemstvími *všech* uživatelů. Loopbackové instance fastmcp nemají autentizaci, takže libovolný lokální proces volá cizí nástroje (`127.0.0.1:35000–54999`, port je funkce `user_id`/`server_id`). `RestrictNamespaces=true` v jednotce navíc brání běžným sandboxům (bubblewrap).
- **Scénář dopadu:** Jediný škodlivý nebo kompromitovaný MCP balíček (instalátor stahuje z PyPI/npm/Docker bez pinningu, B-07) nebo úspěšná A-02 znamená kompromitaci všech uložených tajemství a podvržení identity kterémukoli uživateli. MCP spec k proxy architektuře doporučuje sandboxing spawnovaných procesů, omezení souborového systému a logování.
- **Oprava (po vrstvách):** (1) *levné:* neděditi env – spouštět fastmcp s `env -i` + allowlist (`PATH`, `LANG`, …), tajemství dítěte jen přes jeho konfiguraci; (2) *střední:* tajemství mimo disk (B-02) a `fastmcp` autentizovaný přes lokální token/unix socket; (3) *drahé, vyžaduje rozhodnutí:* oddělené uid / systemd transient unit / kontejner na dítě, popř. `RestrictNamespaces` povolit jen pro pomocníka. Návrh vrstev (1)+(2) ve Fázi 2; vrstvu (3) po vašem rozhodnutí.

#### A-05 · High (podmíněně: SMTP zapnuté + Apache přijímá libovolný `Host`); hash v tokenu Medium · P · pracnost S
- **Místo:** `auth.py:278` (`url_for(..., _external=True)`), `auth.py:58-59` (`_generate_reset_token`).
- **Riziko:** Odkaz v e-mailu se staví z hlavičky `Host`, i když je nastaveno `PUBLIC_BASE_URL` (PoC 2: požadavek s `Host: evil.invalid` → e-mail oběti obsahuje `http://evil.invalid/reset-password/<platný token>`). Token navíc nese `password_hash` (itsdangerous podepisuje, nešifruje; PoC 2 ho přečte bez znalosti klíče) – hash tak končí v e-mailu, přístupových logech a historii prohlížeče.
- **Scénář dopadu:** Útočník spustí reset pro oběť s podvrženým `Host`; oběť klikne na odkaz v důvěryhodném e-mailu, token odejde na server útočníka, ten ho použije a nastaví heslo = převzetí lokálního účtu. Reset funguje jen u lokálních účtů s e-mailem (účet `admin` z postinst e-mail nemá).
- **Oprava:** odkaz z `PUBLIC_BASE_URL` (fallback jen v dev), Flask `TRUSTED_HOSTS`, v tokenu pouze `HMAC(secret, password_hash)[:16]` místo hashe, Apache výchozí vhost vracející 421 (oddíl 9).

#### A-06 · High pro internet (secure-by-default) · K · pracnost M
- **Místo:** `config.py:58` (`STRICT_SERVER_PERMISSIONS=false`), `catalog.py:229-240`, `auth.py:168-189` (auto-provisioning LDAP).
- **Riziko:** Uživatel bez ACL vidí a používá **všechny** povolené servery, tedy se sdílenými admin credentials z Vaultwardenu. Každý, kdo projde LDAP bindem, dostane účet automaticky.
- **Scénář dopadu:** Kterýkoli zaměstnanec s AD účtem (a tedy kdokoli, komu někdo AD účet vytvoří nebo ukradne) se přihlásí do internetové instance a bez schválení použije sdílený Zabbix/Redmine/Semaphore účet.
- **Oprava:** default `STRICT_SERVER_PERMISSIONS=true` + datová migrace (Alembic, vratná), která stávajícím uživatelům *zmaterializuje* aktuální efektivní ACL, takže upgrade nikoho nezamkne (README to dnes jako riziko varuje); volitelně `LDAP_REQUIRED_GROUP` a možnost vypnout auto-provisioning.

#### A-07 · High pro internet, jen s `OAUTH_ENABLED` · P · pracnost M
- **Místo:** `oauth.py:151-192` (DCR, `authenticate_token` → `True`), `oauth.py:291-310`, `templates/oauth_consent.html:15`.
- **Riziko:** PoC 8: anonymní `POST /oauth/register` s `client_name="Claude"` a `redirect_uris=["https://attacker.invalid/cb"]` → **201**; souhlasová stránka zobrazí „Claude“, ale **ne redirect URI** (`attacker.invalid` na stránce není). MCP „Security Best Practices“ vyžadují zobrazit registrované `redirect_uri` a držet souhlas per klient; DCR je v aktuální spec označen jako deprecated ve prospěch Client ID Metadata Documents. Registrace jsou neomezené (jen limiter per worker) a bez úklidu.
- **Scénář dopadu:** Útočník zaregistruje klienta „Claude“ s vlastním callbackem a pošle přihlášenému uživateli odkaz na `/oauth/authorize`; po kliknutí na „Allow“ získá kód → token se scope `mcp` ke *všem* serverům oběti.
- **Oprava:** zobrazit host redirect URI (zvýraznit `localhost`), politika redirect URI (loopback libovolný port podle RFC 8252 + konfigurovatelný allowlist `https://…`), per-client consent, strop počtu a expirace nepoužitých klientů, audit události (DCR, souhlas, token), plán na CIMD. Pozn.: Claude Code používá callback `http://localhost:<port>/callback` – politika loopbacku to musí povolit.

#### A-08 · High (při Bearer/OAuth + síťových backendech) · K · pracnost S

## 7. Spolehlivost spouštění a diagnostiky MCP serverů

### 7.1 Dnešní stav (fakta z kódu)
- **Spawn** (`_spawn`, `user_proxy.py:497-558`): zapíše konfiguraci, `Popen(fastmcp run …)`, po 0,2 s zkontroluje `poll()` (okno je pravděpodobně kratší než typický import fastmcp – neměřeno), pak `_probe_upstream_health(require_tools=True)`: `initialize` s **pevným** `protocolVersion: 2024-11-05` a opakuje se při `ConnectionRefusedError` až do 15 s – **bez dalšího `poll()`**. Proces, který zemřel po 1 s na `ModuleNotFoundError`, tedy hlásí chybu až po 15 s a drží zámek páru i worker.
- Chybová zpráva je jedna: „failed its startup handshake within 15s (or serves no tools) — the registered command is likely broken.“ + 20 řádků logu. Nerozliší příčinu.
- **Recheck** (každých 30 s): jen `initialize`; nesrozumitelná (ne-JSON) odpověď se bere jako zdravá (`user_proxy.py:386-389`).
- `probe_tools` považuje `tools: []` za chybu (správně pro spadlý backend, falešný poplach pro server, který nástroje opravdu nemá).
- **Relay** (`catalog.py:122-189`): timeout 10 s pro vše, jedno opakování po 502; zprávy typu `Upstream MCP server did not respond within 10s: <exc>`.
- **Capabilities** (`admin.py:677-730`, `health.py:249-310`): jen HTTP, bez autentizace, cesta `/mcp`.
- **Síťové servery**: `probe_tools` s hlavičkou auth (monitoring), SSE jen TCP reachability; verze protokolu se neloguje.
- **Souběh/restart**: stav v souborech + flock (správné řešení pro více workerů); `relay_guard` brání zabití instance uprostřed requestu. Slabiny viz B-12 (PID-reuse, zombie, reaper) a B-14 (vyčerpání workerů).

### 7.2 Navržená taxonomie selhání
Jedna výčtová třída `FailureClass` vrácená všemi sondami; každá má *signál*, *zprávu pro uživatele* (akční, bez tajemství) a *detail pro admina* (redigovaný log, příkaz, verze, doba).

| Třída | Signál | Uživatel uvidí (příklad) | Admin navíc |
|---|---|---|---|
| `BINARY_MISSING` | příkaz/`fastmcp` neexistuje či není spustitelný | „Server není na tomto systému nainstalován. Kontaktujte správce.“ | cesta, `FASTMCP_BIN`, výsledek `which` |
| `PROCESS_EXITED` | `poll()` ≠ None během handshaku | „Server se nepodařilo spustit.“ | exit code, klasifikace posledních řádků logu |
| `DEPENDENCY_MISSING` / `VERSION_CONFLICT` | `ModuleNotFoundError`, `ImportError`, konflikt `mcp`/`fastmcp` v logu | „Server má chybnou instalaci závislostí.“ | modul, verze `fastmcp`/`mcp` (viz S-07) |
| `PORT_UNAVAILABLE` | `_find_available_port` | „Dočasně nelze spustit, zkuste za chvíli.“ | zabraný rozsah |
| `CREDENTIALS_UNRESOLVED` | `VaultwardenError`/`SecretStoreError` | „Úložiště hesel je dočasně nedostupné.“ | rozlišit: nedostupný Vaultwarden / špatné master heslo / chybějící položka (využít `vaultwarden.diagnose()`) |
| `CONFIG_MISSING` | chybí `required_env_keys` | už existuje; zachovat | – |
| `AUTH_REJECTED` | upstream 401/403, JSON-RPC auth chyba | „Přihlašovací údaje k službě nejsou platné – upravte je v ‚Vlastní hodnoty‘.“ | stavový kód (ne hlavičky) |
| `CONNECT_REFUSED` / `HANDSHAKE_TIMEOUT` | proces žije, port nepřijímá / neodpovídá | „Server neodpovídá.“ | doba, port, stav procesu |
| `HANDSHAKE_FAILED` | HTTP ≠ 200, JSON-RPC `error` při `initialize` | „Server odmítl spojení.“ | kód a zpráva chyby |
| `PROTOCOL_MISMATCH` | vrácená `protocolVersion` mimo podporované / chybějící `Mcp-Session-Id` při očekávané session | „Server a mcprack nemají společnou verzi protokolu.“ | nabídnutá vs. vrácená verze, vlastnost `--stateless` |
| `TOOLS_EMPTY` / `TOOLS_ERROR` | `tools/list` prázdný / chyba | „Server se spustil, ale nenabízí žádné nástroje.“ | rozlišit prázdný seznam (legitimní?) a chybu |
| `TRANSPORT_MISMATCH` | 404/405/406 na `/mcp` při SSE endpointu apod. | „Server používá jiný přenosový protokol.“ | očekávaný vs. nalezený transport |
| `UPSTREAM_TIMEOUT` | relay překročil limit | „Server odpovídá příliš pomalu.“ | per-server limit |

### 7.3 Požadavky na healthcheck (návrh)
1. Skutečný handshake `initialize` → `notifications/initialized` → `tools/list` (už existuje v `probe_tools`; sjednotit s `probe_http_capabilities`), s **jedním společným** modulem sond a jednou taxonomií.
2. V každé smyčce čekání kontrolovat `proc.poll()` (okamžité `PROCESS_EXITED` místo 15 s).
3. Pevné horní hranice: handshake 15 s, relay per server (konfigurovatelné), nikdy delší než `--timeout` workeru; **globální strop souběžných studených startů** (semafor), aby jeden zaseknutý server nezablokoval workery; chyby cachovat (negativní cache už existuje v monitoringu).
4. Zaznamenat vyjednanou `protocolVersion` (a nabídnutou) do výsledku i logu; probe nabízet nejnovější známou verzi a akceptovat nižší.
5. Slučovat redakci: jedna funkce `redact(text, env, session)` pro relay, monitoring, flash i audit (B-01, B-02).
6. Výstup uživateli: krátká akční věta + kód třídy; výstup adminovi: detail v `Admin → Proxy instance` a `/health/servers` (token-protected), vždy po redakci.

### 7.4 Kompatibilita s FastMCP 4 a transporty
- `fastmcp run mcp.json` (MCPConfig proxy) je podporováno (ověřeno), výchozí cesta `/mcp`; mcprack ji předpokládá natvrdo – číst `--path`/výstup instance.
- MCP spec 2026-07-28 popisuje bezstavový protokol bez protokolových session; probe a relay dnes počítají s `Mcp-Session-Id`. Nutno ověřit na reálných FastMCP 4.x serverech (S-06), případně podporovat oba režimy.
- **stdio** (spawn přes fastmcp proxy), **streamable HTTP** (relay + probe), **SSE** (jen reachability; Claude Code SSE považuje za deprecated – doporučit přechod).
- Verzní drift (S-07) je opakující se příčina incidentů → při startu zalogovat verze `fastmcp`, `mcp`, binárky a odmítnout/ohlásit nekompatibilní kombinaci.

### 7.5 Zombie, úklid a restart
Viz B-12. Navíc: při `systemctl restart mcprack` systemd zabije celou cgroup (děti zaniknou), ale stavové soubory (`pid`, `port`, `meta`, `healthy_at`) zůstávají a mohou obsahovat PID, který mezitím patří jinému procesu. Návrh: `RuntimeDirectory=mcprack` (smaže se při stopu), start-time ověření pidu, reaper vlákno nezávislé na provozu, `SIGCHLD` handler.

## 8. Integrace s Claude Code

### 8.1 Ověřená fakta (dokumentace `code.claude.com/docs/en/mcp`, čteno 2026-11-09)
- **Scopes:** `local` (default; `~/.claude.json` pod cestou projektu), `project` (`.mcp.json` v kořeni projektu, sdílí se přes git), `user` (`~/.claude.json`, všechny projekty). Precedence: local > project > user > pluginy > claude.ai konektory; položka vítězného zdroje se nemerguje po polích.
- **CLI:** `claude mcp add --transport http <name> <url> [--header "K: V"] [--scope local|project|user]`; stdio `claude mcp add --env K=V --transport stdio <name> -- cmd args`; `claude mcp add-json <name> '<json>'`; dále `list`, `get`, `remove`, `login`, `logout`, `reset-project-choices`.
- **`.mcp.json` pro remote:** `{"mcpServers": {"x": {"type": "http", "url": "…", "headers": {"Authorization": "Bearer ${TOKEN}"}, "headersHelper": "/cesta/skript", "timeout": 600000, "oauth": {…}}}}`. Položka s `url` bez `type` je chyba. Alias `streamable-http` je přijat.
- **Expanze proměnných:** `${VAR}` a `${VAR:-default}` v `command`, `args`, `env`, `url`, `headers`. **Pozor:** proměnné s názvy typu `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `AWS_BEARER_TOKEN_BEDROCK`, `HTTPS_PROXY`, `NPM_TOKEN` se v `url`/`headers` vzdálených serverů čtou jako prázdné → použít vlastní jméno (např. `MCPRACK_TOKEN`).
- **SSE** je deprecated (preferovat HTTP). **OAuth:** `/mcp` nebo `claude mcp login <name>`; dynamická registrace klienta je výchozí cesta; callback `http://localhost:PORT/callback`, pevný port `--callback-port`, předregistrované údaje `--client-id` + `--client-secret`; `oauth.authServerMetadataUrl` (https), `oauth.scopes`.
- **Schvalování a politiky:** project-scope servery z `.mcp.json` vyžadují potvrzení v interaktivní relaci; organizační omezení přes `managedMcpServers` / `managed-mcp.json` (podrobnosti syntaxe jsem nečetl). Pluginy mohou bundlovat `.mcp.json`.
- **Nenalezeno:** jednoklikový install / deep link v dokumentaci není → **neslibuji ho**; nabízím kopírovatelný příkaz a `.mcp.json`.

### 8.2 Mezery dnešního mcprack
1. Renderer `claude` (`config_formats.py:90-91`) vyrábí `{"mcpServers": {name: {"type": "http", "url": …}}}` do `claude_desktop_config.json`. Pro **Claude Code** neexistuje samostatný výstup, ani kopírovatelný `claude mcp add`. Zda Claude Desktop v tomto souboru remote `url` přijímá, jsem neověřil (S-05).
2. Path token je tajemství v URL → soubor `.mcp.json` v gitu nebo ve sdíleném repozitáři prozradí přístup (A-03 ho navíc nelze odvolat).
3. Bearer trasa `/proxy/mcp/<id>` (bez tokenu v cestě) funguje jen při `OAUTH_ENABLED` (`catalog.py:490-491`), tedy bezpečný tvar pro git vyžaduje celý OAuth server.
4. Refresh token OAuth vyprší po hodině (B-15) → časté „Needs authentication“ v Claude Code.
5. `mcprack-mcp-probe` neumí Bearer (TODO #4) → nelze ověřit tokenless URL.

### 8.3 Návrh (Fáze 2)
- **Nový renderer `claude-code`** s výstupy:
  1. `.mcp.json` bezpečný pro git – žádné tajemství v souboru:
     ```json
     {"mcpServers": {"mcprack-zabbix": {
       "type": "http",
       "url": "https://mcprack.example.com/proxy/mcp/8",
       "headers": {"Authorization": "Bearer ${MCPRACK_TOKEN}"}}}}
     ```

  2. kopírovatelné příkazy (token z prostředí, ne do historie shellu):

  3. u OAuth režimu jen URL (`claude mcp add --transport http …` bez hlavičky; přihlášení přes `/mcp`).
- **Bearer trasa nezávislá na OAuth:** ApiToken se scope `proxy:access` (+ povinná expirace, jiný než plný admin token); path token zůstane jako kompatibilní režim.
- **Tajemství:** token jen v `MCPRACK_TOKEN` / správci hesel / `headersHelper`; UI i CLI nikdy nevypisují token do `.mcp.json`. Dokumentovat omezení názvů proměnných (viz 8.1).

## 9. Nasazení do internetu

### 9.1 Doporučená topologie
Internet → Apache (TLS 1.2+/1.3, HSTS, jediný vstup) → `127.0.0.1:8912` gunicorn → mcprack. Port 8912 nikdy mimo loopback (jinak firewall pouze pro IP proxy). Již hotové: TLS vzor, `X-Forwarded-Proto`, hlavičky, loopback bind, sandbox jednotky.

### 9.2 Co ještě chybí (návrh obsahu do `debian/apache-mcprack.conf` a README.Debian)
- **Apache:** `RequestHeader unset X-Forwarded-Host/-For/-Prefix` před nastavením vlastních (důvěřovat jen jednomu hopu); výchozí catch-all vhost vracející 421/444 (brání A-05 a host header útokům); `LimitRequestBody` (odpovídá `MAX_CONTENT_LENGTH`), `LimitRequestFields`; `ProxyTimeout` a `flushpackets=on` pro streamované odpovědi; omezení `<Location "/admin">` a `<Location "/api/v1/admin">` na IP/klientský certifikát; `/health/servers` jen z loopbacku/monitoringu.
- **Flask:** `TRUSTED_HOSTS`; `ProxyFix(x_prefix)` jen pokud je nakonfigurován; `Cache-Control: no-store`.
- **fail2ban:** filtr nad Apache access logem (gunicorn vidí vždy 127.0.0.1): `POST /login` s odpovědí 200 = neúspěch (úspěch je 302), `POST /forgot-password`, `POST /oauth/register`; jail s `bantime` rostoucím.
- **Síť:** nftables pravidla per uid `mcprack` (`meta skuid mcprack`): zakázat `169.254.0.0/16`, `127.0.0.0/8` kromě rozsahu 35000–54999 jen pro sebe, RFC1918 kromě allowlistu backendů; v jednotce `IPAddressDeny=`/`IPAddressAllow=` jako alternativa.
- **Sdílený limiter:** buď DB tabulka (preferováno, bez nové závislosti), nebo Redis (`python3-redis` + `redis-server`) jen jako volitelná varianta po schválení.
- **Provoz:** `ExecStartPre` čistí stav proxy, `gthread` workery, `--max-requests` s jitterem, rotace logů už existuje.
- **Dokumentace:** sekce „Nasazení do internetu“ v README.Debian (checklist), upgrade poznámky k A-06 a B-16 (v `debian/changelog`).

## Příloha C – co je v pořádku (stav ověřený čtením kódu / PoC)

- LDAP: `escape_filter_chars` (`auth.py:105`), prázdné heslo odmítnuto před bindem (`auth.py:99`), při výpadku LDAP login selže (lokální účty fungují dál).
- `_safe_next_url` (`auth.py:21-47`) odmítá protokolově relativní, řídicí znaky i cizí hosty.
- Šablony: autoescape, žádné `|safe`, `Markup`, `render_template_string`; inline JS/CSS nejsou potřeba (CSP `script-src 'self'`).
- Žádný SQL z uživatelského vstupu (jen `SELECT 1`/`version()`); ORM všude.
- ApiToken: pouze sha256, scopes, „token nesmí vytvořit silnější token“, max. platnost podle zakladatele (`api.py:432-453`).
- `hmac.compare_digest` u `MONITORING_TOKEN`; `/health` vrací jen booleany.
- `_redact_env_values` v relay odpovědi, `500` bez detailu, limit těla požadavku 2 MB, whitelist cest ikon (`appstream_icons.py:202-208`).
- Reset tokeny: časově omezené, po použití neplatné (otisk hesla), stejná odpověď bez ohledu na existenci účtu (enumerace).
- Cookie: `Secure` default, HttpOnly, SameSite=Lax; HSTS jen za HTTPS.
- Cache tajemství šifrovaná (Fernet), zápis atomicky s `0600`; flock serializace přístupů k `bw`.
- Alembic migrace mají `downgrade()` (kromě záměrně prázdné datové opravy `88e6fe369433`).
